# Repairs and verified liquidation winners — 11 September 2026

All seven obligations from the 12:30 UTC / 19:30 Asia/Bangkok incident were successfully liquidated by other wallets before our bot recorded rejection. This confirms competitor activity for this window, alongside the independent arithmetic and transaction-construction bugs found locally. It does not establish that all seven would have met this bot's profit floor after fees.

## Verification

The audit script has no dotenv or wallet signer import. The live bot was not restarted, rebuilt, reconfigured or used to broadcast any transaction.

## Changes implemented

- Correct USD conversion in both execution branches: base-unit amounts multiplied once by base-unit price, using Decimal until final number conversion.
- Protocol liquidation fee reduces the liquidation bonus rather than principal plus bonus.
- Compute budget price/limit instructions now survive composition with reserve/obligation refresh instructions. Previously the spread result's `preInstructions` was overwritten, discarding both instructions entirely. An offline flash-loan assembly test verifies the prefix and flash-repay borrow index after inserting budget/setup instructions.
- Re-simulation replaces the existing CU limit, keeps the chosen route's lookup tables, and uses RPC total `unitsConsumed`, not the last program's consumption log. Auto priority bid conversion accounts for the actual requested 1.4M CU limit.
- Quote selection resolves with the first usable CLMM/Jupiter result. Individual route deadlines bound waiting. Packet overflow invokes the bounded fallback paths, including KSwap; a normal successful local route no longer waits for both Jupiter results. RPC signing failures no longer masquerade as oversized transactions.
- Queue capacity is reserved synchronously. Bursts cannot exceed three active executor tasks; both synchronous and asynchronous errors release their lanes.
- Automatic small-prize simulation bypass removed: all automatic attempts must simulate successfully. The explicit low-level executor option remains for callers that deliberately request it.
- Forensics uses a bounded time window, checks the actual instruction target and liquidator (including CPI), preserves negative time deltas, and separates unavailable/incomplete history from a window with no observed liquidation. It no longer claims self-healing from missing evidence.
- Runtime forensics uses the public endpoint and a single separate queue. Healthy simulation failures now trigger this verification too; it does not consume the bot's paid endpoint quota.
- Watchlist exits no longer increment lost-race totals or claim another liquidator took a position in console/alert formatting. The legacy `taken` event name remains for compatibility and means only a tracker exit.
- Failure ledger records now retain the trigger time, rail, total elapsed time, stage timings and up to 40 simulation log lines, including retryable failures. Timing maps no longer contain string route names.
- Software latency path: the WebSocket account payload is retained and decoded directly when it is younger than 1.5 seconds, with one shared block-time lookup per notification slot. Fresh hot-tick hydration is passed into the executor instead of fetched again. The trailing 500 ms hydration sleep was removed, route quote selection is first-usable, and blockhash/ALT/scope caches are warmed and single-flight.
- The WebSocket trigger subscription now uses `processed` delivery. It is only a candidate signal; fresh reserve/obligation refresh plus simulation still gate every automatic send.
- Screening and watchboard margin now use the executor-priority debt reserve, protocol share of the liquidation bonus, and flash-loan fee. They are labeled as estimated margin before swap/network costs; they are not realized P&L.

## Validation and limits

`npm run build`, `npm test`, and `git diff --check` pass. The suite covers the arithmetic regression, synchronous queue bursts, slow/failed route selection, bounded history/RPC errors, all seven actual liquidation fixtures, honest tracker alert wording, and compute-budget/flash-index assembly. Tests and fixture replay require no live trading.

The offline synthetic benchmark in [APP_SPEED_BENCHMARK.json](APP_SPEED_BENCHMARK.json) measured the component change with 100 ms artificial RPC latency: the reconstructed old serial path was about 802 ms, while a fresh WebSocket payload path was about 101 ms and a targeted account read about 100 ms. This is a controlled component measurement, not a production latency or win-rate claim; SDK decoding was stubbed equally and no network was used.

These are workspace changes, not a production deployment or proof of a successful own-wallet liquidation. The corrected budget prefix increases transaction bytes and activates the configured priority fee; the existing packet limit checks still apply. All automatic attempts are simulation-gated.

Remaining economics/coverage limitations: profit estimates still exclude base transaction fee, ATA rent and priority fee from the reported USD surplus; actual account/oracle state can change after simulation; the collateral estimate uses a haircut rather than reproducing every protocol rounding branch; non-vanilla and advanced liquidation sizing are still out of scope. A positive quote does not guarantee positive realized P&L. Background route requests may finish after their selection deadline; deadlines bound waiting, not cancellation of underlying SDK work. No claim is made that all future races are solved.
