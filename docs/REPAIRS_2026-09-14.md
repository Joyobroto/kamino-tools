# Liquidator repairs — 14 September 2026

The executor previously read lookup tables with raw HTTP against the primary endpoint, bypassing RPC failover. Repeated failures produced an empty address list and then a misleading packet-size rejection. The last three observed failures took 46–47 seconds and never reached simulation.

Changes:

- Lookup tables use the shared failover RPC, with a three-second request deadline, cached and deduplicated concurrent reads, account validation and explicit errors. Missing/unavailable tables no longer silently disable compression or cause an obligation to be classified as structurally broken. Background warming retries after an outage.
- Genuine packet-size rejections now include measured bytes for each attempted route and assembly time.
- Collateral/cToken ATAs use SPL Token, independently of whether the liquidity mint uses Token-2022. Both execution and setup/LUT key generation agree with the installed Kamino SDK's collateral token program.
- Hot hydration refreshes market/oracle snapshots after ten seconds instead of reusing the broad scan's sixty-second cache. Concurrent reloads remain deduplicated. This increases market reload frequency; it does not implement an oracle notification stream.
- Broadcast failures retain the signed transaction's signature. Receipt lookup records actual `feeLamports` and confirmed/failed/unknown status. Missing transaction metadata is explicitly unknown. The USD budget estimate remains an estimate (base allowance plus the chosen tip), separate from measured fees. Failure alerts no longer present a hardcoded USD amount as measured gas.
- Confirmation timeouts include the signature and clear their timers on completion.

Validation:

- Full test suite passed: 102 tests after LUT, receipt and cToken changes.
- Subsequent hot-cache freshness change passed all six hydration tests, including a new regression for shared refresh of twenty-second-old market data.
- TypeScript build and `git diff --check` passed after the final code changes.

Remaining limits: oracle-driven detection is not implemented; hot checks still run on the configured interval. No successful own-wallet liquidation has been established. Profit estimates still need complete network-cost accounting; receipt retrieval is best effort and does not reconcile crashes or late confirmations automatically. Existing on-chain LUTs are not extended by this patch; corrected Token-2022 collateral ATA addresses may remain inline until a separately funded setup update is performed.
